# Plan 6 — Mobile: Glow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The phone app gets the Glow look and the case engine:
- **Tabs:** Cases, Approvals (with a badge), Calls, Pulse, Settings.
- **Cases:** a list with the 8-dot stage bar, and New request.
- **The case screen:** a vertical stage list where the live stage pulses, followed by the case file in sentences.
- **The approval screen:** from the mockup, a two-tone question with the case's stage, a risk card, evidence ticks, the gradient **Approve with fingerprint** and **Reject with a note**.

Maestro flows prove it on the Android emulator in Expo Go.

**Architecture:**
- **Shared helpers:** the pure case-view helpers move from the web app into `@onehuman/sdk`, so web and mobile show cases with the same tested code, plus two new phone helpers.
- **Native tokens:** `@onehuman/ui` gains what React Native needs (gradient stops, a 13px font floor). The app loads Red Hat with `@expo-google-fonts` and draws gradients with `expo-linear-gradient`.
- **Guard test:** like the web's, it keeps the phone's colours on tokens.
- **Maestro:** a seed script creates a fresh power plant with a safety officer, a plain member and two jobs at their approval gates. The flows then sign in as each person in Expo Go.

**Tech Stack:** Expo SDK 57, React Native 0.86, Expo Router (typed routes), TanStack Query 5, `react-native-reanimated` 4.5, `expo-linear-gradient` and `expo-font` (SDK 57 versions), `@expo-google-fonts/red-hat-display` and `@expo-google-fonts/red-hat-text` 0.4.1, Vitest 5, Maestro CLI 2.10.0.

**Spec:** [docs/superpowers/specs/2026-10-12-org-types-and-case-lifecycle-design.md](../specs/2026-10-12-org-types-and-case-lifecycle-design.md), section 6 (Mobile and Accessibility) and section 5 (the Mobile row: "sign in as a role holder, see only their approvals, approve with the fingerprint-signed key, view the case list and pipeline"). The phone mockup is screen 3 of `.superpowers/design/direction-a.html` (git-ignored, in the main checkout).

## Global Constraints

- Every check must stay green: `pnpm turbo run build typecheck test`. Shared packages are consumed from `dist/` (`pnpm build:packages` after changing `packages/*`).
- **Mobile typecheck needs fresh route types.** `.expo/types/router.d.ts` is generated by the Expo dev server and git-ignored. After adding a route, keep `pnpm --filter @onehuman/mobile start` running until it has regenerated, then typecheck.
- **Colours come only from `@onehuman/ui` tokens** (`useTheme().c`): no hex and no named colours in `master-ai-mobile/src` (guard test in Task 2).
- **Colour always means the same thing:** warm (the action gradient, `warning`) means a person is needed; green means done; cool violet means navigation and agents; red means critical or P1.
- **Red Hat everywhere.** Weights come from font families (`font.semibold`, …), never `fontWeight`; Android drops a custom font when `fontWeight` is set. Text is at least 13 (`fontSize` tokens).
- **Interactive targets are at least 44px tall.**
- **Glows** become a cheap fade from the top and soft tinted cards with light borders. No blur (slow on Android).
- **The app is always dark** (`src/lib/theme.ts`). Never `useColorScheme()` (CLAUDE.md).
- **Reduced motion:** the live stage pulses with Reanimated and keeps still under `useReducedMotion()`, showing a static ring instead.
- **People never see tool names, ids or JSON** (CLAUDE.md). The phone no longer shows `approval.tool` or the risk "factor" jargon.
- `expo-notifications` stays lazily required (`src/lib/push.ts`, CLAUDE.md).
- **Expo APIs come from the v57 docs** (`master-ai-mobile/AGENTS.md`). `expo-linear-gradient` and `expo-font` are installed with `npx expo install` (SDK 57 versions). The other new dependencies are exact versions at least 14 days old. One React version (Expo's): don't touch `react`.
- **Expo Go on the emulator:** port 8082, `adb reverse tcp:3000 tcp:3000` and `tcp:8082 tcp:8082`, open `exp://127.0.0.1:8082` (CLAUDE.md).

## Deviations from the spec (decided while planning)

1. **Approvals stays the screen the app opens on.** It is the reason the app exists. The tab bar reads Cases, Approvals, Calls, Pulse, Settings, as the spec and mockup show.
2. **Goals leaves the tab bar.** It stays a screen, opened from Pulse ("Agent jobs"), so plan reviews still work on the phone. Giving a goal from the phone is replaced by **New request**, as on the web (Plan 5 Deviation 2).
3. **New request on the phone** (the spec is silent): a button on the Cases tab.
4. **On the emulator the approval is signed without a fingerprint prompt.** A fresh emulator has no fingerprint enrolled, so `confirmWithBiometrics` passes (`not_enrolled`). The decision is still signed with the phone's keystore key, and the server still verifies the signature. A real phone with a fingerprint or Face ID asks every time.
5. **The case-view helpers move from `master-ai-web/src/lib/cases.ts` into `@onehuman/sdk`.** `lib/cases.ts` re-exports them, so no web import changes.

## Review Focus

These inputs aren't covered by any happy-path test and are the most likely to hurt a real user. Each line names the test that pins it.

1. **A case whose title holds a long unbroken word** (a pasted reference, a run-together equipment name): the list clamps it, and the approval still shows its Approve button within reach. Pinned in Task 7, `flows/role-holder.yaml` (the seeded hot-work job's title holds a 70-letter word, and the flow scrolls to Approve and taps it).
2. **No signal on the approval screen:** the case can't be loaded, but the saved approval still shows its own words and can be decided. A queued decision syncs later. Pinned in Task 1, `case-view.test.ts` "keeps the approval's own words when the case can't be loaded".
3. **A member signed in:** nobody else's approvals, no kill switch, and the cases still readable. Pinned in Task 7, `flows/member.yaml`.
4. **Reduced motion** (Android's *Remove animations*): the live stage keeps still. Pinned in Task 1, `case-view.test.ts` "keeps still when the phone asks for less motion".
5. **A workspace without stage names** (installed before Plan 2): the stage list shows the generic names. Pinned by `case-view.test.ts` "falls back to the generic stage names", which moves into the sdk in Task 1.

```ts
const lowerFirst = (s: string) => (/^[A-Z][a-z]/.test(s) ? s.charAt(0).toLowerCase() + s.slice(1) : s);

/** An approval as a two-tone question: a grey lead-in ("Approve") and a white payoff ("hot work permit?"). */
export interface ApprovalHeading {
  /** Above the question: the case number and title, or the agent asking. */
  kicker: string;
  lead: string;
  question: string;
  /** e.g. "From the Permit & clearance stage". */
  from: string | null;
}

/**
 * A case step asks about the case and its stage; an agent step asks in its own
 * words. With no signal the case can't be loaded, so the approval's own words stand in.
 */
export function approvalHeading(
  a: Pick<ApprovalRequest, 'kind' | 'stage' | 'summary' | 'agentName'>,
  ctx: { case?: Pick<Case, 'code' | 'title' | 'categoryName'> | null; stageName?: string } = {},
): ApprovalHeading {
  if (a.kind !== 'case_gate') return { kicker: a.agentName, lead: '', question: a.summary, from: null };
  const from = ctx.stageName ? `From the ${ctx.stageName} stage` : null;
  const c = ctx.case;
  if (!c) return { kicker: '', lead: '', question: a.summary, from };
  return {
    kicker: `${c.code} · ${c.title}`,
    lead: a.stage === 'close' ? 'Sign off' : 'Approve',
    question: `${lowerFirst(c.categoryName ?? 'this request')}?`,
    from,
  };
}

/** The live stage pulses while agents work or a person is awaited, unless the phone asks for less motion. */
export function stagePulses(state: DotState, reducedMotion: boolean): boolean {
  return !reducedMotion && (state === 'live' || state === 'waiting');
}
```

import { readdirSync, readFileSync, statSync } from 'node:fs';
import { join, relative } from 'node:path';
import { fileURLToPath } from 'node:url';
import { describe, expect, it } from 'vitest';

const SRC = fileURLToPath(new URL('../src', import.meta.url));

function sources(dir: string): string[] {
  return readdirSync(dir).flatMap((name) => {
    const path = join(dir, name);
    return statSync(path).isDirectory() ? sources(path) : /\.tsx?$/.test(path) ? [path] : [];
  });
}

function offenders(pattern: RegExp, keep: (m: RegExpMatchArray) => boolean = () => true): string[] {
  return sources(SRC).flatMap((file) =>
    [...readFileSync(file, 'utf8').matchAll(pattern)].filter(keep).map((m) => `${relative(SRC, file)}: ${m[0]}`),
  );
}

describe('the phone app takes its look from the Glow tokens', () => {
  it('uses no hex or named colours', () => {
    expect([...offenders(/(?<![&\w])#[0-9a-fA-F]{3,8}\b/g), ...offenders(/['"](?:white|black)['"]/g)]).toEqual([]);
  });

  it('keeps all text at 13 or more', () => {
    expect(offenders(/fontSize:\s*(\d+(?:\.\d+)?)/g, (m) => Number(m[1]) < 13)).toEqual([]);
  });

  it('picks Red Hat weights by font family, never fontWeight (Android drops a custom font with it)', () => {
    expect(offenders(/fontWeight\s*:/g)).toEqual([]);
  });
});

  const detail = useQuery({ queryKey: ['goal', goal.id], queryFn: () => api.goals.get(goal.id), enabled: open });
  const reviewing = goal.status === 'awaiting_plan_approval';
  return (
    <Card tone={reviewing ? 'warm' : 'glass'}>
      <Pressable onPress={() => setOpen((o) => !o)} accessibilityRole="button" accessibilityState={{ expanded: open }} accessibilityHint="Shows the report" style={{ gap: space.xs }}>
        <T weight="semibold">{goal.text}</T>
        <Badge tone={TONE[goal.status] ?? 'muted'} label={reviewing ? 'Plan to check' : goalStatusWord(goal.status)} />
      </Pressable>
      {reviewing && goal.plan && (
        <View style={{ gap: space.xs }}>
          <T tone="lead" size="sm">
            {goal.plan.rationale}
          </T>
          {goal.plan.tasks.map((t) => (
            <T key={t.key} size="sm" tone="body">
              • {t.title}
            </T>
          ))}
          <View style={{ flexDirection: 'row', gap: space.sm }}>
            <Button title="Approve plan" style={{ flex: 1 }} onPress={() => decide.mutate(true)} loading={decide.isPending && decide.variables} />
            <Button title="Reject" variant="secondary" style={{ flex: 1 }} onPress={() => decide.mutate(false)} loading={decide.isPending && !decide.variables} />
          </View>
        </View>
      )}
      {!open && goal.summary && !reviewing && (
        <T tone="lead" size="sm" numberOfLines={3}>
          {goal.summary}
        </T>
      )}
      {open && detail.error && (
        <T tone="danger" size="sm">
          {errorMessage(detail.error)}
        </T>
      )}
      {open && detail.data && <ReportView report={detail.data.report} />}
    </Card>
  );
}

### Task 7: Maestro flows on the Android emulator

- **The role holder:** the safety officer sees only her own approval (not the owner's overhaul), reads the question with its stage, scrolls past the long word to **Approve with fingerprint**, and approves with the phone's signed key. Then she sees the job past its permit in Cases.

Create `master-ai-mobile/e2e/run.mts`:

```ts
/**
 * `pnpm e2e:mobile`: the phone flows in Expo Go on the Android emulator.
 * Needs `pnpm dev` (API :3000), Metro (`pnpm --filter @onehuman/mobile start`, :8082),
 * a running emulator with Expo Go, and the Maestro CLI in ~/.maestro/bin.
 */
import { execFileSync, spawnSync } from 'node:child_process';
import { homedir } from 'node:os';
import { join } from 'node:path';
import { API_URL, PASSWORD, seed } from './seed.mts';

const ADB = process.env.ADB ?? join(homedir(), 'Library/Android/sdk/platform-tools/adb');
const MAESTRO = process.env.MAESTRO ?? join(homedir(), '.maestro/bin/maestro');

function fail(message: string): never {
  console.error(`✗ ${message}`);
  process.exit(1);
}
const answers = (url: string) =>
  fetch(url).then(
    (r) => r.ok,
    () => false,
  );
const adb = (...args: string[]) => execFileSync(ADB, args).toString();

if (!(await answers(`${API_URL}/health`))) fail(`The API is not answering at ${API_URL}. Start everything with \`pnpm dev\` first.`);
if (!(await answers('http://localhost:8082/status'))) fail('Metro is not running on :8082. Run `pnpm --filter @onehuman/mobile start` in another terminal.');
if (!/emulator-\d+\s+device/.test(adb('devices'))) fail('No Android emulator is running. Start it with `~/Library/Android/sdk/emulator/emulator -avd Pixel_10_Pro`.');
if (!adb('shell', 'pm', 'list', 'packages', 'host.exp.exponent').includes('host.exp.exponent')) fail('Expo Go is not on the emulator. Press `a` once in the Metro terminal to install it.');
for (const port of ['3000', '8082']) adb('reverse', `tcp:${port}`, `tcp:${port}`);

const env = await seed();
console.log(`✓ Seeded ${env.COMPANY}: ${env.HOT_WORK_CODE} waits for the safety officer, ${env.OVERHAUL_CODE} for the owner`);

const vars = Object.entries({ ...env, PASSWORD }).flatMap(([k, v]) => ['-e', `${k}=${v}`]);
const run = spawnSync(MAESTRO, ['test', join(import.meta.dirname, 'flows'), ...vars], { stdio: 'inherit' });
process.exit(run.status ?? 1);
```

Add the root script `"e2e:mobile": "node master-ai-mobile/e2e/run.mts"` to `package.json`.
